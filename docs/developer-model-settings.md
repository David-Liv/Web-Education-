# 管理员全站 API 与模型设置

更新：2026-11-01。全站配置、草稿模型列表、所选模型测试及明确套用已实现。本次已用用户提供的真实服务取得24个模型（HTTP 200），并将URL和密钥保存至云端；尚未代选、启用或调用任何模型生成内容。真实文字能力与教学品质仍待管理员选择后验证。操作见 [运行说明](pilot-runbook.md)，实际发布版本见 [部署记录](deployment-verification.md)。

## 已确认方向

- 使用用户提供的 API 服务；实际地址、协议、认证和模型清单接口在收到服务信息后核对。
- 开发者设置 API 地址、认证信息，获取模型列表、选择模型，再进行实际调用。
- 不采用先前提出的 HK$100 固定测试金额上限，不以该上限自动阻断调用。
- 教学与计划规则仍由确定性代码负责；AI 用于已确定的学习及日历说明等功能。

## 管理员操作

1. 开发者进入「内容与开发设置 → 模型服务」或`/developer?tab=model`，查看「全站AI模型」当前生效状态。
2. 填写服务名称、API Base URL、认证信息；根据真实文档确认接口协议，不假定所有提供方都使用同一路径。
3. 点击「获取模型列表」，后端只读取清单，不自动选择、逐一测试或修改生效配置。
4. 若服务没有列表接口或权限不足，解释原因，并允许手动填写 model ID；不虚构模型列表。
5. 开发者选中模型，点击「测试此模型」做一次草稿文字测试；不把模型出现在清单中当作已经可用的证据。草稿测试失败也不替换原有生效配置。
6. 勾选启用，点击「储存并套用至全部使用者」。所有账户之后的新AI请求统一使用这个服务和模型；学生不用填Key，也不能自行改模型。已开始的请求及历史记录保留原模型。
7. 同一URL的Key留空会保留；更换URL不沿用旧Key。取消启用后套用可暂停全站AI，未选模型时只能停用保存。

设置保存在后端。密钥由后端保存并用于调用，学生端只获得可使用的模型配置，不把密钥写入前端 bundle、浏览器存储、普通日志或学习记录导出。

沿用私有`settings`中的单一`model`设置及AES-GCM加密，不新增每位学生的API设置。`PUT /api/v1/admin/model`保存生效配置，启用时必须有模型ID；`POST /api/v1/admin/model/models`及`/test`接受`{config:草稿}`且不持久化，兼容旧客户端的空body仍使用已保存配置。学生和复核者均无模型配置访问权。更换URL、Key或协议后清除旧清单／测试状态，更换模型也不能沿用旧模型的测试通过标记。

## 可检查的能力与结果

- 文本、流式、结构化输出、图片等能力按实际接口与测试结果分别记录，不只凭模型名猜测。
- 首批只需测试已选中模型需要的能力，不自动对清单中每个模型发起生成请求。
- 展示连接失败、认证失败、模型不可用、接口不兼容、提供方限额及超时等具体状态。
- 提供方自身的额度限制和错误照实显示。应用用量记录可用于排查，但不引入用户已拒绝的固定金额上限。
- 切换模型不改写学生已产生的正式答题证据，AI 回馈保留所用配置／模型来源供追溯。

开发者设置页面、角色保护、服务端密钥存储、配置接口和两种协议适配器均已实现。新增隔离检查覆盖草稿不生效、失败保护、两学生统一切换、历史保留、权限、密钥不外泄及跨URL不带旧Key。当前对提供方请求完整文本，再以网站 SSE 回传；不声称已验证原生 token 串流、图片或结构化输出能力。普通聊天、导读后exercise和参考反馈仍走快速路径，完整检查／有限返工只用于独立AI测验生成。
