# v1.4 interface and calendar verification

5 November 2026. Student instructions: [Chinese](user-guide.md), [English](user-guide.en.md).

## Delivered behavior

- Desktop calendar tasks use pointer dragging, preserve the grab point and snap to five minutes in day/week view. Month moves retain the original start and duration. Touch input uses a 380 ms long press; ordinary swipes cancel the pending gesture and remain scrollable. Active dragging has a destination preview and edge scrolling. There is no duration-resize gesture.
- Saving uses the existing owned task PATCH with an optional `moveFrom` snapshot of date/start/minutes. Both server and mock reject guarded moves for completed, locked, exam or floating tasks, stale snapshots, overlaps, rest days, budget overflow and midnight overflow. Guarded requests cannot smuggle unrelated edits. Existing explicit detail editing remains available. Undo supplies the acknowledged destination as its expected source, so it cannot overwrite a newer schedule.
- A move previews locally while saving, then commits the returned task. Failure restores the saved arrangement and shows the reason. An acknowledged save is retained if the subsequent refresh fails. Successful moves have a single latest-move **3-second** “Schedule updated · Undo” reminder. A new save or leaving the calendar dismisses the old action.
- Desktop navigation collapses to a 72 px icon rail, initially expanded. The browser remembers the choice. The logo changes to the expand control on hover/focus, and icon labels appear outside the scrollable rail. Mobile retains a full drawer and close control. Labels support Chinese and English; reduced-motion settings disable the added transitions.
- The chat composer no longer shows the inline cost/model note or the lower saved-conversation disclaimer. Plan settings, credit accounting, other pages' cost notices and error messages keep their behavior. Both student and administrator guides and product release notes were updated.

## Checks

- **65 frontend/domain tests passed** across seven current-source files, including grab-offset snapping, preserved identity/duration, stale moves/Undo and constraint failures. English literal coverage includes the extracted Sidebar component and month-view tooltips. Vitest explicitly includes `src/**/*.test.{ts,tsx}` so ignored private release snapshots do not inflate local test counts.
- **69 backend tests passed**, including an owned API move/Undo, unchanged duration, rejected stale snapshots, overlapping/midnight moves, cross-account denial, unrelated field rejection and locked/completed protections.
- Production frontend/server type checks, build and bundle guard passed. The generated pilot API documents `moveFrom`. No new dependency, database DDL, paid resource or AI call is required.
- An isolated in-memory fixture served the production frontend. Desktop browser checks confirmed cross-day dragging, immediate Undo, preserved duration, overlap rejection with the original position retained, month date-only moves, disappearance of Undo after three seconds, persisted icon-rail preference after reload, Chinese/English labels and hidden composer notes.
- A 390 px browser viewport confirmed the mobile menu opens the full 232 px drawer with readable navigation labels and no document horizontal overflow. This is responsive-browser evidence, **not a physical touch-device test**. Actual phone/tablet long-press behavior still needs a device trial; the implementation and cancellation paths were inspected.

Private screenshots and the disposable fixture remain ignored under `.data/reviews/v1.4/`. Production student data and AI credits were not used for browser checks. Unrelated `scripts/update-types.mjs` was preserved.
