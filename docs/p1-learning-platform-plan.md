# P1 学习平台实施清单：三科辅导与自动化优先

日期：2026-10-31。来源：当前grilling六项范围选择及用户对检查／返工流程的要求。

状态：已按本清单接通本地代码及自动化检查，完整返工仅用于AI生成独立测验题组，导读后附带的小测试明确不在此列。真实模型品质、远程部署及学生试用仍未完成本轮验收，实际证据见 [P1验证](p1-verification.md)。

## 1. 已确认的变化

| 选择 | 本轮确定的范围 |
| --- | --- |
| 实施顺序 | P1先完成，再统一开展面向学生的整套测试；开发中的单元、接口与回归检查继续进行。 |
| 产品定位 | 学生个人及私人补习场景的自主学习辅助工具；不追求学校成绩认证或替代专业作文批改产品。 |
| 主要科目 | 数学、中文、英文优先；化学保留已有内容和记录，暂不优先扩充。 |
| 三科内容 | 数学解题、步骤反馈和弱项练习；中文阅读、文言辅助和写作建议；英文阅读、词汇语法和写作建议。每科先跑通代表性内容。 |
| 自动化 | 能自动完成的讲解、出题、反馈、错因及复习尽量自动；团队人工以抽查、纠错和处理异常为主。 |
| 进度 | 客观题尽量代码评分；主观题AI给参考反馈，自动更新暂定知识点状态。后续独立新题增强依据，学生可纠正。 |
| 练习来源 | AI原创短练习加少量团队稳定参考内容；外部真题继续保留来源链接。只有测验生成走完整检查／返工；聊天与导读后的exercise快速响应。 |
| 入门 | 可先选科目、目标等级和可用时间；大学目标可后填。约3–5道短题寻找起点，边学边补证据，不要求先做三科整卷。 |

自主辅导已独立于共享审校包运行，旧双人发布门槛保留在原有正式内容路由；三科仅完成首组代表内容，不是全科发布。

## 2. P1交付边界

1. **日历与任务清单共用任务**：允许待安排任务，预计用时保留；安排进日历后仍是同一任务，完成／延期不会分叉。
2. **真正的周里程碑**：由已有14天计划生成周目标，说明技能、任务、用时与理由；不只返回空的weeks。
3. **单日休息与恢复**：休息只影响指定日期；预算仍有效，不扣掌握、不抹记录、不把全部欠账追缴到第二天。
4. **双周报告**：按最近14天记录汇总学习、复习、独立作答、暂定技能与未覆盖范围；没有足够日期或数据时显示实际覆盖。
5. **既有反思入口**：继续复用私人笔记／晚间收尾，保持可选，不新增强制情绪打卡。
6. **上述三科自动学习流程**：不是只把P1页面做好；新增内容必须实际接入学习、反馈、进度及下一步安排。

全科课程、完整DSE定级、听力／口语评测、整卷OCR与免测、社群、多角色门户、导师配对和交易不并入本批。此前的考卷导入分析继续保留，不能因暂缓而删除。

## 3. 开发批次与依赖

### A. 请求用途分流与测验生成返工管线

- 按 [AI输出规范](ai-output-contract.md) 区分快速文字、单次结构化和测验生成；只为测验生成建立严格契约、错误路径及有限返工状态机。
- 适配现有模型配置与Chat／Responses通道，不另建模型账号体系。
- 结构化字段按需做便宜的本地检查，不因返回JSON或要保存记录就触发模型审核／重写。普通聊天与导读后的exercise优先速度。
- 完整返工使用单独的测验生成入口，不能包进通用模型调用；验收正常快速请求只有一次生成、没有隐藏审核请求，固定题库选题不需要AI。
- 请求归属、必要去重及写入约束各路径保留；失败字段不落入评分、技能或日历，普通文字仍可交付。

### B. 三科练习、反馈与暂定知识点状态

- 建立首组技能与评价维度，优先少量完整路径。数学可复用二次方程；中文／英文新增代表性阅读及写作辅导内容。
- 将AI私人陪练与共享已审校教学包分开：陪练无须等待逐题双人发布，既有人工审校包仍保留其来源和版本。
- 扩展现有题目／评分来源与状态，允许AI参考、无法判断、学生纠正；不得将AI反馈写成manual或reviewed。
- 客观判分优先代码；暂不支持验算的数学形式和主观维度显式保留限制。
- 暂定证据影响推荐，但与已审校独立证据分开。一次错误不抹全部能力，一次提示后答对也不升级稳定掌握。
- 纠正旧结果时重算派生状态，保留历史；重复提交不重复加证据。

### C. 轻量入门与下一步

- 不强制先有大学目标或完整全科成绩；缺少相应数据时不用精确加权收益排序阻塞学习。
- 首次约3–5道短题是起点，不是定级标准。没有覆盖的知识点保留未知；时间不足可保存后继续。
- 每次作答后给出反馈、涉及技能及一个清楚的下一步；测验结束时沿用补强／维持转科／查看冲高的选择。
- 大学目标后填时重新检查条件与来源年份，保留既有记录；未核实公式不能生成可靠精确收益。

### D. 任务、单日休息与周里程碑

- 修改目前必须有start的任务模型，使待安排和已安排状态明确，补齐API、校验、旧记录兼容和两种视图。
- 单日例外独立于每周预算；跳过、延期、休息后的任务调整仍受时间和先备约束。
- 从实际任务生成周目标，展示排入／未排入原因。暂定技能可以影响草稿，不输出固定DSE升一级承诺。
- 保留既有计划预览、版本冲突、锁定任务和已完成任务保护；本轮未授权取消确认机制。

### E. 双周报告与复习联动

- 以服务端记录做确定性汇总，区分任务完成、复习完成、辅助作答及独立证据；不以网页在线时间冒充有效学习。
- 报告打开时即可计算，无需先新增邮件、推送或定时任务服务。可选AI表述走快速路径，不套测验生成返工。
- 复习时间包含在每日总预算，休息不会导致连续惩罚；缺少数据时给可解释的下一步，而非虚构进步曲线。

### F. 整体验收、指南与学生试用

- 每批开发完成做对应检查；所有功能齐备后统一进行三科全流程、跨页面与浏览器验收。
- 随实际产品更新同步 `docs/user-guide.md` 与日期记录，必要时同步README和runbook；规划内容不提前写成学生已能使用。
- 保留3–5名学生、两周观察安排；这不是开发工期。试用检查能否独立开始、理解反馈、执行计划、纠正误判及恢复学习。

## 4. 后端最小改动范围

| 模块 | 需要改变的内容 |
| --- | --- |
| 模型调用 | 复用现有配置，按用途选择快速文字、单次结构化或测验生成；只有最后一种有完整检查与有限返工。 |
| 内容与发布 | 共享审校包与个人AI陪练分路由／来源；不能用假审核账户绕过旧门槛。 |
| 评分与证据 | 增加AI参考／暂定来源与纠正历史；减少普通主观练习被永久挂在人工队列的情况。 |
| 技能与推荐 | 可用暂定证据选择下一步，显示限制；不直接换算全科成绩或覆盖学校基准。 |
| 任务与排程 | 待安排状态、单日例外、真实周目标，兼容现有持久化记录。 |
| 报告 | 从已有学习记录计算14天汇总，保留口径与数据不足状态。 |

继续使用现有个人账户、私有记录和数据库，不先建设学校／机构权限。当前小规模数据不要求先全面重构存储或引入付费基础设施。

## 5. 必须通过的整体验收

| 情境 | 通过条件 |
| --- | --- |
| 学生没有大学目标／完整成绩 | 能选择科目、目标和时间并开始短练习；未知项不阻塞、不当零分。 |
| 数学／中文／英文各一次代表流程 | 实际产生题目与反馈，保存来源和暂定状态，下一步可执行。 |
| 测验生成返回坏格式或内部矛盾 | 自动检查、有限返工；通过前不采用题目，次数用尽有清楚退路。 |
| 聊天／随堂exercise或单次结构化反馈 | 不进入完整返工；必要本地检查失败时只放弃不合格字段，保留可用文字与学生输入。 |
| 学生连续错误／看过提示 | 补救与辅助事件正确记录，不无限刷题或虚增独立掌握。 |
| 学生指出AI反馈有误 | 可纠正、历史保留、相关暂定状态可重算，计划重新预览。 |
| 同任务在清单和日历操作 | 状态一致，无重复任务和双重计时。 |
| 今天休息／未完成任务较多 | 只调整指定日期，不改每周预算，不无限增加明天负担。 |
| 14天报告只有3天数据 | 明确显示3天记录及未覆盖范围，不制造14天趋势。 |
| 重试、取消、旧响应和跨账号 | 不重复计证据、不越权、不采用过时结果，既有记录仍可读取。 |

协议替身检查、真实提供方测试、内容抽查、浏览器全流程及学生试用分别记录，不相互替代。真实模型尚未配置时不得将替身成功说成实际AI学习能力通过。
