## 2. 当前代码与目标之间的缺口

以下保留实施前原型的缺口，用于解释迁移动机；真实模式现状以 [首期验证](pilot-verification.md) 为准。mock 继续保留原演示规则，不能与新后端混为一谈。

- `src/domain.ts` 的排程会计算单科升一级的加权增益，但不使用 `targetGrades`，未建立学习成本、先修图、目标达到后的维持策略。排序后的题目目前仍按演示轮转安排，不能视作真正的最优分配。
- 现有 mastery 是最近五道不同独立题目的得分比，未检查审核版本、题型覆盖及跨时段保留表现。
- `WrongItem` 只有单个自由文本错因及 `resolved`；页面支持学生选择分类，不支持带证据、待确认、可复核的归因。
- 答案只有整体文字、提示布尔值和一个附件引用；没有逐步作答、错误步骤、提示层级或补救周期。
- 首次无提示答对原错题可被现有逻辑标为 resolved；不能因此认为已经满足新的「稳定掌握」规则。
- 聊天回覆是预制模板。真实 AI、账户、服务端持久化、跨设备与审核发布后台尚未实现。
- 院校规则是带年份及缺失标记的快照。未核实规则、历史收分指数字段、原始分数必须保持分开；没有原始录取目标线时不能生成假精确录取差距。

## 3. 建议的实现顺序

顺序与范围已统一获批，具体范围、初始参数、接口迁移及验收案例见 [首期实施方案](pilot-implementation-plan.md)。代码交付及实际验证另见首期验证。

以下为原首期顺序；2026-10-31之后的新阶段按 [P1实施清单](p1-learning-platform-plan.md) 先补契约／返工、三科自动反馈和P1，再统一学生验收。不能将下列旧顺序中的逐项人工门槛套在新阶段所有私人陪练上。

1. **内容与规则模型**：先为两个单元建立审核题、评分步骤、先修关系、目标相关性、成本范围和版本；以不同学生案例测试规则。
2. **学习与证据内核**：实现作答、辅助程度、错因候选、复测及掌握状态，保留可追溯记录。
3. **目标与计划内核**：计算入学条件、完整提分组合、预算可行性和取舍；把单元进步接到测验结果卡和日历。
4. **最小真实后端**：学生私有记录、内容版本、审核发布、测验提交、附件和必要 API 接口；模型密钥只留在服务端。
5. **受限 AI 教学**：基于审核内容讲解、分层提示及错因解释；结构化建议经过规则校验后才能改变计划。
6. **小规模试用**：确认数据隔离、恢复流程及内容审校后，观察学生能否独立完成整条流程，再扩大覆盖。
