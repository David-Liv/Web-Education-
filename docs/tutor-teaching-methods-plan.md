# Tutor 教学方法与 PDF 课程实施方案

日期：2026-11-05。

状态：**产品设计已确认，首版本地实现已完成，正在完成真实模型与发布核对。** 实际检查、未完成验证和上线状态见 [Tutor 验证记录](tutor-verification.md)，不能把本方案当作线上交付证明。

本方案记录 David 在本轮讨论中确认的决定。它补充并取代 [导师逻辑参考](tutor-logic.md) 中与导师选择、教学交付形式有关的旧建议；正式测验、证据、目标和日历约束继续沿用现有规则。

## 1. 产品目标与边界

同学在同一个学习入口选择教学方法：

- **David 教学法**：由用户提供的 STEM Super-Tutor prompt 改编，侧重分段导读、渐进提示、结构化解题和错因反馈。
- **Matt 教学法**：由 Matt Pocock 的 `teach` skill 改编，围绕目标组织可信资源、短课程、参考资料、学习记录和练习反馈，主要交付可下载 PDF。

Tutor 决定教学流程、内容组织和使用哪些模块，不只是语气、头像或不同名称。同一入口不拆成两套独立产品。Tutor 与 AI 模型独立：选择导师不改变学生套餐、模型权限或模型单价。

首个有实质资料和端到端验收的主题是数学必修「二次方程」。其他主题按真实资源和验证结果说明覆盖，不由试点效果推断全科覆盖。现有科目入口继续按其当前能力提供服务。

本期不实现 Tutor skill 自动制作、教师视频批量提取、第三方 Tutor 发布市场、PPT 生成、在线课件编辑器或新的滑块／模拟器引擎。

## 2. 已确认的产品决定

| ID | 决定 | 实现边界 |
|---|---|---|
| T01 | 同一入口选择 David 或 Matt 教学方法 | 两者可采用不同流程和交付方式 |
| T02 | 每个对话固定 Tutor | 更换导师建立新对话，保留原对话 |
| T03 | 学习记录可跨 Tutor 使用 | 只读取相关目标、证据、偏好和摘要；Tutor 的局部教学进度单独保存 |
| T04 | 答题卡、提示、图表、后续提问和文档等均为可选模块 | 允许零个聊天答题卡、零个后续提问按钮；界面不擅自补出导师未选用的模块 |
| T05 | 首版生成 PDF，用户提到的 PPT 为笔误 | 需要真实文件和直接下载；浏览器打印说明不能替代文件交付 |
| T06 | Matt 保留完整核心教学逻辑 | 目标、可信资源、短课、参考资料、学习记录、术语及反馈闭环均有对应实现 |
| T07 | 新课生成课件，普通追问在聊天中答疑 | 不因每一次追问重做整份 PDF |
| T08 | 新课件或用户要求修订时生成新版本 | 旧文件保留，不能以同名链接静默替换已下载内容 |
| T09 | 课件先提供题目，默认不附完整答案 | 学生按稳定题号回到聊天作答；主动要求时可获得答案和解析 |
| T10 | 下载和阅读属于学习活动 | 不直接提升正式掌握度或整科等级 |
| T11 | 所有新练习及生成解答沿用现有自动检查 | 聊天／PDF 练习不因此接入正式测验的完整生成工作流 |
| T12 | 原 prompt 做产品适配 | 保留有效教法；使用简明依据和可核对解题步骤，不展示内部思考草稿 |
| T13 | 沿用已有目标和学习资料 | 有必要时通常最多补问一至两个问题；目的明确即可开始 |
| T14 | 首版使用预先整理的可信主题资源 | 记录用途、来源和缺口，不编造引用、抓取成果或计算器步骤 |
| T15 | 一份新课件按选定教学模型收取一次操作费用 | 内部练习检查和文件排版不额外扣学生 credit |
| T16 | 打开和重复下载免费 | 同内容排版失败后的重新生成文件免费 |
| T17 | 新内容和下一课属于新操作 | 生成完全失败不扣点，或释放／退回已预留额度 |
| T18 | 正式测验、计费、权限、证据与日历由平台统一管理 | Tutor 不得直接改分、改目标、移动日历或授予模型权限 |

## 3. Matt 核心教学逻辑的产品映射

原文位于本地 `skills/skills/productivity/teach/`，上游为 [mattpocock/skills 的 teach](https://github.com/mattpocock/skills/tree/main/skills/productivity/teach)。原版主要输出 HTML 课程和可打印参考页，本方案将主要交付形式适配为 PDF；不宣称原版自带 PDF 或 PPT 引擎。

| 原版机制 | HOKSE 对应状态／行为 |
|---|---|
| Mission | 为什么学习、可观察成功标准、时间等限制、不在本次范围的内容；沿用目标资料，学生确认后才改变目标 |
| Resources | 有说明的可信来源，分别记录知识资源、适合的经验资源及资料缺口 |
| Short lessons | 每课只教与任务相关的一小块知识，给学生一个具体可完成的进展 |
| Zone of proximal development | 从相关作答和学习记录选择下一步，不把「没有记录」判为完全不会 |
| Knowledge → skills | 先提供必要知识，再练习、反馈和迁移；不以课件页数代表学习效果 |
| Fluency / storage strength | 区分刚看过后的熟悉和隔时保留，适当安排回忆、间隔和相关技能混练 |
| Learning records | 保存非平凡理解、学生声明的已有知识、纠正的误区和目标变化；带来源／证据及取代关系 |
| Reference documents | 逐课积累公式速查、解题流程和概念参考，链接至有关课程 |
| Glossary | 保持术语一致；已介绍的术语与学生已能正确运用的术语分开，后者才进入个人已理解术语记录 |
| Preferences / notes | 保存相关教学偏好和未解决问题，不无限追加整段对话到每次请求 |
| Shared assets | 复用已有公式、图表、题目、提示和排版能力，导师决定用哪些以及怎样组合 |
| Feedback loop | PDF 中题目有编号；学生回到聊天作答，导师能读取准确题目版本并给反馈 |
| Wisdom | 如有合适且已整理的经验资料可提供链接，尊重学生不参与社区的偏好；本期不新建社区 |

原 skill 在命令行环境中的文件目录，应映射到平台账户下的结构化状态，不能为每个学生创建可执行的任意工作目录。借用原文或改编材料时保留上游 MIT 许可与版权说明；界面称教学方法改编，不暗示 Matt 本人提供人工辅导或背书。

PDF 中互动组件使用适合印刷的图、表、题目或文字替代，并提供返回学习室的入口。PDF 交付不承诺离线自动评分、任意 JavaScript 互动或模拟器。

## 4. David prompt 的适配

原文：[STEM Super-Tutor prompt](references/stem-super-tutor-prompt.txt)。

- 保留导读、解题、选题任务；学生看到自然语言名称。
- 保留渐进提示、必要时回到基础、错误归因及避免无限补题的机制。
- 章节大小按知识密度和学生时间组织，不机械强制每次讲固定页数。
- 按材料导读时遵循顺序；目标补弱时允许按先修关系和目标相关性优先处理。
- 使用可核对的步骤、条件和检查结果，省略内部思考草稿及每次必须找瑕疵的要求。
- 依据不足时保留错因候选，不根据一个最终答案断言错因或学生情绪。
- 自报已知、提示后答对、重复原题和看过答案不提升为正式独立证据。
- 允许使用已有聊天答题卡、折叠答案、图表与后续提问，也允许按需要省略。
- 按学生的教学语言呈现，中文、英文界面均使用自然表达。
- Anki 导出等尚不存在的模块不得因原 prompt 提到就宣称已经支持；保留为后续扩展备注。

## 5. 学生路径

1. 在现有学习／新对话入口查看导师名称、教学方式及真实覆盖范围，选择 Tutor。
2. 读取已有目标和相关学习资料；必要时补问一至两个短问题。
3. David 按选用模块讲解；Matt 开始新课时提供短课件与真实 PDF 下载。
4. 学生阅读后可以普通追问，也可以按「第 2 课 · Q3」作答。
5. 导师读取该课程、题目和版本，给予提示、错因反馈或按需提供解答。
6. 学习记录更新为可追溯的教学信息；正式掌握证据继续走统一规则。
7. 继续下一课或请求修订时生成新版本；重开、下载已有文件不再次收费。
8. 更换 Tutor 时创建新对话并带入相关学习摘要，不搬运无关历史或另一导师的整段提示词。

学生界面保持学序的森林绿、清晰留白和克制的信息量。聊天内展示课程名称、目标简述、版本及下载／继续入口即可；不暴露内部规则、Skill 文件、审核任务编号或后台日志。

## 6. 组件与运行边界

### 6.1 教学方法定义

服务器打包版本化的教学方法注册表，至少记录方法 ID、版本、名称、教学规则、适用范围、允许／默认模块和课件策略。选中方法和版本固定到对话及生成操作。

只加载选中方法、相关主题资源和需要的模块契约。禁止把所有 Tutor prompt 拼接到同一请求；选择导师和拼接上下文不额外触发一次规划模型调用。

原版 skill 和本地安装目录目前在忽略路径下，线上运行不能依赖它们存在。实施时应将必要的、带许可的运行资源显式纳入应用包。

### 6.2 可选模块

首版复用并整理：Markdown／表格、数学公式、现有图表／几何／概念图／电路示意图、题目、分层提示、答案解释、后续提问及文档交付。

同一模块的内容结构与展示方式分离，例如题目内容可放入聊天答题卡，也可排进 PDF。每位 Tutor 可以采用不同的教学组织方式，甚至不使用聊天答题卡。平台统一负责合法结构、安全呈现、练习检查和权限。

当前聊天格式要求及界面回退会强制补三个建议，实施时应改为由 Tutor 策略和本次输出决定，不再给所有完成回复强制补齐。

### 6.3 资源与 DSE 关联

二次方程试点应准备基础概念、解法比较、选择题与长题的不同处理、常见错误、核对方法及目标相关的练习方向。计算器技巧必须有适用型号和核实依据；不将不确定的「formula 1」泛化成所有计算器通用步骤。

资源采用明确 ID、出处、覆盖和使用说明。模型只能引用本次提供且有效的资源，不能凭空声称已看过某个视频或某页教材。首版不自动抓取 YouTube。

现有数学外部索引仍是元数据／链接目录，不转成公开复制的题库。不把网站难度包装成官方 DSE 单题等级。课件练习采用可使用的自编／已获许可内容，来源限制继续生效。

### 6.4 生成、检查与交付

建议流水线：固定操作上下文 → 生成结构化课程草稿 → 校验结构／引用／题号 → 对新练习或解答使用现有 Flash 检查 → 确定最终内容版本 → 确定性排版 PDF → 私有持久保存 → 将真实下载入口关联到原回复 → 结算一次费用。

纯聊天追问继续使用快速路径；不包含新练习或解答的课件无需凭空增加一次练习审核。PDF 练习沿用聊天练习检查，不接入正式测验的多轮完整工作流。

课件结构中保留课程目标、章节、参考、题目、提示和正确解答；默认学生 PDF 仅排入允许展示的部分，答案在服务端供后续反馈使用。不要将默认隐藏的答案混入题目 PDF 的附件、元数据或不可见文字层。

内部纠错在文件首次交付前完成。交付后的内容修改生成新版本；已发生的作答始终绑定原题和原版本，不能被后来的修订改写。

普通对话的提示、附加练习与正式测验仍保留各自既有的计费／证据边界；不能利用 PDF 或 Tutor 标签绕过检查。

## 7. 数据与接口实施建议

下表为实施契约草案，不代表这些接口已经存在。具体字段可在实现时按现有项目惯例调整，不改变已确认产品行为。

| 实体／接口 | 最少职责 |
|---|---|
| Tutor 定义 | 服务器内方法 ID、不可变版本、能力策略和覆盖 |
| Chat 扩展 | 固定 Tutor ID／版本、教学状态、相关课程和课件关联 |
| 课程状态 | Mission、资料引用、课次、参考、术语、偏好及学习记录 |
| 学习记录 | 原始出处、证据类别、题目／课程版本、时间与取代关系 |
| 文档记录 | 所有人、对话、课次、内容版本、文件、生成状态和操作关联 |
| Tutor 列表读取 | 向学生仅返回名称、介绍、覆盖和所需展示信息 |
| 创建对话扩展 | 校验 Tutor 和适用范围；更换导师通过新对话完成 |
| 生成／修订课件 | 固定方法、资源和模型价格，提交幂等，支持失败恢复 |
| 文档读取／下载 | 鉴权、归属校验、正确 PDF 类型和下载文件名、私有缓存策略 |
| 按题号反馈 | 读取真实课程版本与题目，不能让模型猜测旧题 |

旧对话保留已有行为和历史，兼容映射到原方法的旧版本，不能一夜之间变成 Matt 教学或使用新 prompt 重解释历史。生成中的操作固定方法、模型、资源、内容与价格快照，部署、切换聊天或请求重试不改变原操作语义。

当前外部数据库已有按账户隔离的文件字节存储、全站 100 MiB 附件容量保护和私有读取路径，可以评估复用。当前 PDF 引擎、生成文件元数据和消息交付关联尚缺。不能把 Render 临时文件目录当作文件的持久保存位置，也不能声称现有文件字节已经应用层加密。

新增文件遵守已有容量保护；容量不足应给出可恢复的失败并执行失败计费规则，不自动开通付费存储。删除对话、失败操作和无引用文件的清理需在实施中一并验证，不能遗留不可见但永久占用容量的文件。

PDF 渲染先做繁中／英文、公式、表格、图表和分页的能力验证，再选择符合现有免费运行环境资源限制的实现。隔离模型提供的内容与执行代码，不运行模型任意 HTML／JavaScript 或抓取任意外部地址。

## 8. 计费和恢复

| 操作 | 学生 credit |
|---|---|
| 新课程 PDF 成功交付 | 选定普通对话教学模型单次操作价格 |
| 同操作内的练习检查、纠正和排版 | 不另扣 |
| 已有课件重新打开、下载 | 不扣 |
| 已保存内容因排版错误重做文件 | 不扣，不再次生成教学内容 |
| 新内容、下一课、内容修订请求 | 新操作，按当前允许模型与价格预留 |
| 普通聊天追问 | 沿用普通对话规则 |
| PDF 服务没有完成任何可用课件交付 | 不扣，或释放／退回预留 |

课程生成的「正在准备」文字或一个无效下载链接不算成功交付。用一次操作 ID 贯穿生成、审核、文件保存和结算；网络重试、双击和并发下载不能重复扣点或产生重复课程。

当教学内容已保存但 PDF 排版失败时，优先复用内容重新排版，不为了修复文件重复调用教学模型。免费重新排版不是免费请求新教学内容的入口。

PDF-only 请求与现有混合聊天回复的可用交付结算需要区分测试，避免因一段状态说明而收取整份失败课件费用。原有聊天重试的价格快照和已退款操作结算规则继续保留。

## 9. 实施顺序

1. **方法与对话基础**：版本化定义、Tutor 选择、旧对话兼容、所有新对话入口和 mock／接口契约同步。
2. **教学状态与上下文**：目标复用、必要补问、资源、课次、记录与偏好持久化；两种教法输出差异可验证。
3. **可选模块契约**：停止强制补建议；同一题目／图表可使用聊天或文档呈现，不改正式测验证据规则。
4. **PDF 交付闭环**：结构化草稿、练习检查、真实渲染、私有持久保存、下载与版本。
5. **反馈与计费闭环**：按题号答疑、记录依据、生成失败恢复、同内容免费排版、并发幂等和删除清理。
6. **文档与验收**：中英文学生／管理员指南、开发运行说明、自动检查、浏览器检查、小规模真实模型与线上核对。

这些步骤是实现依赖顺序，不是将未完成的底层状态或收费逻辑先开放给学生。首版完整路径可用并验收后再发布。

## 10. 必须通过的验收

- 两位 Tutor 在同一任务、相同模型下呈现不同的教学组织；选择 Tutor 本身不改变模型或费用。
- Matt 从目标、资源到课程、反馈和下一课形成闭环，而不是只在消息末尾附 PDF。
- David 能分段导读、渐进提示并支持错因反馈；不会输出内部思考草稿或每题强制冗长栏目。
- 不使用聊天答题卡或三个建议的 Tutor，界面确实不显示这些模块；已有能力仍可被另一 Tutor 使用。
- 已有目标不会重复盘问；没有记录和零能力保持区别；课程覆盖不被夸大。
- 能真实下载含繁中／英文、正确公式、表格、图表和稳定题号的 PDF；无乱码、公式缺字、重叠或严重分页错误。
- PDF 默认不泄露参考答案；学生按需可在聊天获得解答；反馈绑定正确的题号与版本。
- 新练习／解答检查不能被课件路径绕过；检查修正进入最终文件；普通追问维持快速路径。
- 有错误的生成内容只允许保留为明确标记的找错题示例，不污染正确参考资料或学生错题历史。
