## 模拟 Billing 完整闭环

学生入口为独立的「套餐与账单 / Plan & Billing」，沿用现有安静、清晰的学习平台视觉风格，并提供中英文。

1. 账户总览：当前套餐、本月已用／预留／可用 credit、下次重置日期、当前模型及单价。
2. 套餐比较：月费、额度、允许模型、当前套餐及升级入口。
3. 确认订单：目标套餐、模拟补差价、本期可用额度变化、生效时间。
4. 付款渠道：点击模拟渠道后直接进入成功状态，不收集真实银行卡、验证码或支付凭据，不调用真实支付网关。
5. 模拟成功：订单持久化为明确的模拟成功状态，套餐立即生效。页面与收据持续标明「模拟交易，未真实收费」。
6. 订单／账单：个人订单历史、金额、状态、渠道、生效周期及模拟收据查看／下载。
7. 订阅管理：升级、下周期降级、取消／恢复续订、待生效变更。
8. 用量明细：自己的操作用途、模型、credit、结算状态，以及提供方有返回时的 token 用量；不暴露其他账户资料。

升级立即生效，按香港时间本月剩余时长展示模拟补差价。本月可用额度按新上限减去本月已用及仍预留额度计算，不因再次付款／切套餐重领一整份额度。用户发起降级或取消在下个月 1 日生效，本期权益保留到月底。

香港时间每月 1 日开始新额度周期，未使用的月度额度不累积。续订状态及待生效套餐在新周期按服务端规则处理，不需要新增付费 cron 服务。所有订单和接口保留支付提供方抽象，未来接真实支付时改用服务端验证结果；模拟成功接口不能被当作真实付款证明。

## credit 计量与结算

- credit 是平台内部使用点数，和提供方 token／真实费用分别记录；不能用本平台余额声称实际提供方费用上限。
- 计费单位是一项用户主动发起的 AI 操作，采用开始时的模型单价快照。操作开始前预留，成功交付并保存可用结果后结算。
- 系统失败、生成最终无效、取消时释放预留；同一请求重复提交、刷新或重连不重复扣点。后端依持久化操作 ID 与数据库原子更新处理并发，不仅依靠浏览器状态或进程内锁。
- 独立 AI 小测内部最多三次生成／检查只对学生收一次，实际每次上游调用都进日志并归属同一个操作。聊天、导读随堂练习及普通回馈保持现有快速路径，不新增 AI 返工循环。
- 固定题的生成、数值／选择题规则判分不调用 AI，不收费；固定题中的主观批改／步骤回馈若实际调用 AI，会在提交前显示其模型和消耗。
- 配置页的管理测试作为平台测试记录，不向学生余额扣点；管理员普通学习操作依其分配的套餐处理。
- credit 不足时在发出模型请求前拒绝；不自动更换模型、不允许负数，仍可使用无需 AI 的功能。
- 管理员改价只影响之后开始的请求；套餐额度变动按新上限减本月已用／预留重算，保留原有消费及账单快照，不追溯重新计价。所有调整保留操作者、时间及前后值。
- 旧学生账户初始化为 Free，本月新请求开始计量；不补扣历史请求，不伪造旧日志。异常中断后的未结算预留需要可验证的恢复规则。

## 管理员 AI 使用日志

仅开发者／管理员可查看全站日志及导出，内容审核员和学生不能读取这套管理接口。

列表：用户姓名／账号、调用当时的 Plan、时间、用途、模型、渠道、端点、状态、耗时、credit、眼睛图标。提供模型／用户搜索、状态和日期筛选、刷新、总数及分页。用户姓名与 Plan 放在前面。

眼睛详情沿用参考图结构：基本信息、请求路径、请求摘要 JSON、token 用量、credit 结算；报错时显示错误类型、上游状态／错误码及安全处理后的错误信息。网页详情接口和页面均不包含实际返回正文；正文仅通过受保护的日志导出获得。

请求摘要字段按实际发送内容记录：`model`、`stream`、`msg_count`、`chars`、`has_tools`、`tools_count`、`first_role`、`temperature`、`max_tokens`。未指定值保留 null／未指定，不把截图的 60,000 token 或 tools 数量写成固定值。当前上游适配器是非流式生成，前端 SSE 展示应与上游原生 streaming 分开标记。

返回用量规范化为输入、输出、合计 token；从提供方实际响应读取，不用字数估算。提供方未提供的值显示未提供。多次生成保留每次用量，不能把缺失记录当成零。

实际返回文字／失败详情存于私有数据库，使用现有服务端密钥加密并清理 API Key、Authorization、Cookie 等凭据。导出包含请求摘要、响应文字、用量、状态及截断标记；支持单条 JSON 及按筛选条件的日志导出。网页不执行响应里的 HTML 或指令。

AI 内容日志初始保留 30 天、最多 1,000 次上游记录，并标明内容长度限制／截断。订单和 credit 账本独立保存，不能随着 AI 日志清理而消失，否则会破坏余额、对账与去重。

## 后端与接口落点

- 套餐目录／版本、型号价格与权限、用户订阅周期、模拟订单、credit 操作／账本、AI 上游调用日志分开持久化。
- 公共／学生接口覆盖套餐目录、本人余额／订阅／用量、模拟订单创建／支付／查询、升级／降级／取消；管理接口覆盖规则配置、账户套餐、额度调整、日志列表／详情／导出。
- 身份、模型权限、credit 预留和订单归属由服务端判断，客户端传入的价格、角色或付款成功状态不能成为可信来源。
- 日志在模型适配器统一收集，credit 则按上层有效操作结算，避免将一次内部重试误计成多次收费。记录原始上游 HTTP 状态，和应用交付／格式检查结果分别呈现。
- 不在等待模型期间持有数据库事务；用短事务处理预留、结果保存和结算。SQLite 和现有 PostgreSQL 两种后端都需支持。
- 新表位于既有私有存储范围，添加查询索引及权限约束；同步云端备份／空库恢复，兼容旧备份缺少套餐表的情况，不改写既有学习记录。
- 同步 OpenAPI、管理员／学生中英文界面、两份用户指南、README 和 pilot runbook。当前指南不提前宣称已实现。

## 验收与发布顺序

1. 套餐与计费领域规则、迁移、模型权限及账本测试。
2. 真实模型调用接入计量／日志，使用本地提供方替身测试成功、错误、超时、取消、三次返工、重连／重复请求和并发。
3. 学生 Billing 与管理员规则／日志页面，核对中英文、请求摘要和 token 缺失状态。
4. 浏览器走通模拟升级、月底降级／取消、余额不足、管理员改价、成功／错误日志及受保护导出。
5. 回归原学习／测验／日历逻辑，检查导出不包含密钥，备份恢复不漏新表。
6. 使用既有 Render Free／Supabase Free 发布；不新增支付商户、真实收费、付费后台服务或周期任务。线上只做必要的读取验证；生成和付费案例先在隔离 fixture 验证，避免污染学生记录。

## 后续 remark

- 真实支付、验签回调、退款／拒付、正式收据及税务资料需另行设计，不由模拟成功状态代替。
- 年付、额外充值包、优惠券、赠送 credit 和团队套餐后续再做；独立额度类别不与每月额度混账。
- 提供方真实成本对账、长时间用量分析、超出当前范围的多供应商路由后续再加，不将内部 credit 当作真实货币费用。
