# 首期真实学习流程实施方案

更新：2026-10-28。用户已明确要求「实现这个 plan」，本文件作为批准执行的范围基线。现有代码交付和验证状态见 [首期验证](pilot-verification.md)，启动、复核及部署准备见 [操作说明](pilot-runbook.md)。原验收案例保留为范围依据，不表示所有外部条件已完成。

2026-10-31后续范围已调整为数学／中文／英文优先、自动化学习反馈与P1齐备后统一学生测试，见 [P1实施清单](p1-learning-platform-plan.md) 及 [AI输出检查／返工规范](ai-output-contract.md)。本文件保留首期设计与既有实现边界；新增私人AI陪练不应直接套用本文件的逐题双人发布与所有步骤等待人工的门槛，也不表示现有代码门槛已经修改。

已确认的产品规则见 [产品决策 C01–C35](product-plan.md)。用户已统一批准按本方案实施；初始教学参数仍属待真实数据校准的项目规则，不能改称官方或已校准标准。

## 1. 首期交付与边界

- 延续现有香港繁体中文界面、侧栏、知识地图和克制的动画；优先补齐状态说明、下一步操作和反馈。
- 做实数学必修「二次方程」及化学「酸碱与滴定」，每个单元约 10–15 分钟初测。中英数化的目录、成绩及目标入口继续保留；真实教学覆盖以已发布内容为准。
- 跑通目标／时间录入 → 单元诊断 → 目标相关的补弱 → 独立练习 → 每日复习／隔时复测 → 测验结果卡 → 计划预览和确认。
- 配置真实模型服务，获取模型列表、选择及测试，再用于学习讲解、错因候选和日历方案说明。提供方由用户配置，不预设固定 API 金额上限。
- 提供邀请制学生账户、隔离的服务端记录、真实附件存储、表格审核导入与版本发布。
- 功能与部署验收后，安排 3–5 名学生试用两周。两周是试用观察周期，不是本次开发工期。

未覆盖学科仍可记录学校成绩和手动任务；不能生成它们已完成审校的教学或诊断结果。整科成绩依学校预估／较完整模拟考试，单元进步只说明该范围的证据。2028 考期仍按 [来源记录](data-sources.md) 的实际状态展示，不把演示日期迁入真实学生安排。

OCR、完整作文／口语评分、在线题目编辑器、支付和全科题库扩展继续保留在后续备注，见产品决策 R 表。

## 2. 内容与初测

每个单元先建立一个版本化内容包：技能节点、先修边、教学短块、审核题、评分点、错误候选依据、选题蓝图和估计时长。按诊断、一次补救换题、复习和延迟复测所需的不同题目覆盖来确定题量，不用一个固定总数冒充内容足够。

候选题分类优先参考 [既有来源调研](research/dse-maths-tagging-sources.md)，沿用 [复核口径](content-review-guide.md)。外部原始难度、目标程度、题号与本项目映射分开保存；原创题另建 ID，不能沿用其参考历届题的 ID。现有 68 道示范题需逐题决定沿用、修改或保留在演示环境，不能整批自动转成已审题。

建议的初测体验：

1. 说明单元范围和约 10–15 分钟预计用时；允许保存后继续。
2. 按蓝图抽取关键方法和少量应用题；必要题记录简短步骤。未答、答错和待人工批改分别显示。
3. 初测不因预计时间到达就强制宣布能力不足；正式限时考试属于另一个任务类型。
4. 先展示可客观判定的结果和覆盖；未批改的步骤保持待确认。题库不足则缩小声明范围或暂停正式初测，不拿未审 AI 题补齐。
5. 结果进入补弱流程；未知技能可安排短检查，不能默认全部不懂。

## 3. 学习与证据规则

### 3.1 服务端事实与掌握状态

掌握状态由版本化代码规则计算。输入至少含内容／题目／评分版本、作答时间、技能覆盖、得分、提示和答案展示事件、题目变式家族及复核状态。

- 只把适合该技能、已复核、可可靠评分的独立作答用于正式掌握判断。
- 提示／答案展示由服务端留事件，不能信任浏览器传来的 `hinted: false`。学生已经在旧测验、错题页或学习中看过的同题答案，也不重新包装为首次独立证据。
- 同一评分点可以关联多个知识点，但不得重复计入可恢复分值。同一题或只换数值的同一家族不能无限刷证据。
- 主观步骤待人工核对时保持待批改；可先给练习反馈，不先写正式得分再补依据。
- 保留未评估、证据不足、需加强、初步掌握、较稳定及复测到期的区别。复测到期不等于立即变为零掌握；历史证据不删除。

建议给首批内容包提供下列**可修改的初始策略**，由内容复核时确认适用性，不能称作已校准标准：

| 项目 | 初始建议 |
|---|---|
| 初步掌握 | 至少两道不同审核题的独立证据，并达到该技能的关键评分条件；未覆盖能力继续列出 |
| 较稳定掌握 | 至少三道不同审核题、两个作答时段且至少相隔 24 小时；覆盖包内必需题型，相关有效证据得分率至少 80%，关键评分条件通过 |
| 变式覆盖 | 单一家族不满足全部覆盖要求；若题库无有效迁移题则不能升级为较稳定 |
| 初始复习节奏 | 首次学习后约 1、3、7 天安排回顾；根据错误、预算和已安排任务调整，规则及原因可追溯 |
| 规则版本变化 | 可按新规则重新计算并显示依据；不改写原始作答记录 |

### 3.2 错因及补救

沿用 C24–C26：保存观察步骤、候选原因、依据、来源及确认状态；学生可以纠正或选不确定。只有最终答案时允许未知，最多追加一次短追问。

同一补救周期第一次错误后提供解释和一道同类新题；再次失败暂停自动追加，展示完整解法并提供前置补救、其他不依赖该弱点的内容或休息。学生主动继续仍记录，但不靠重复练习直接升级掌握。

补救周期按技能／补救动作追踪，不能通过新建聊天或重新打开题目把连续错误计数清零。系统不依据「??」等短回复自行诊断学生情绪。

## 4. 目标排序与日历

### 4.1 整科策略与单元执行分开计算

**整科策略层**接收已注明来源和日期的整科成绩、个人目标及主目标课程规则。先检查未知数据、最低要求与个人目标冲突，再比较合法成绩组合。对已验证公式可以枚举受限范围内的组合，每个组合重新算 Best N、必计科、换算、加分及互斥条件；不能简单相加每科单独提升的收益。

学习成本以有出处的区间假设进入比较。没有成本就标成本待估，没有原始收分参照就不生成原始录取差距。输出可行方案、时间／收益取舍及缺失条件；只称为在已收录规则和成本假设下的比较，不称实际升分或录取最优保证。初期完整整科路径可用明确标注的情景数据验证算法，不能把两个单元的学习成本当整科提一级成本。

**单元执行层**只安排已有正式内容的活动。建议按以下顺序处理，而不沿用当前一个总分混排：

1. 过滤未发布内容、尚不可进行的依赖任务和无可用题目的测验；未知先修可安排检查。
2. 先放锁定、已完成、已确认复测和到期回顾；均占用学生的时间预算。
3. 结合目标必要条件、可靠的近期弱点及先修补救选择候选活动。
4. 在同一优先层中比较有依据的收益／时间区间；缺可靠收益映射时显示能力覆盖与成本，不伪造精确加分。
5. 同等条件按等待时长、任务 ID 等稳定规则决定顺序，避免刷新产生不可解释变化。

二次方程的一个评分点被多个技能支持时只计一次改善空间；考试原始分值、DSE 等级及院校加权分是不同单位，不能直接相乘混算。

### 4.2 下一步卡片与计划确认

每次科目测验后，结果页显示本次表现、覆盖／缺失证据、错因和目标相关性。发生有价值的调整机会才出现继续补强、维持并转移时间、查看冲高方案的卡片。学生只通过单元测验时不能自动显示整科达标。

排程沿用 14 天详细窗口。较长期只列里程碑和假设，不生成看似精确但没有内容支持的日程。采用香港时区和服务端真实时钟，演示时钟独立保留。

建议首期将「小幅自动重排」定义为：同一天内、同学科及相同活动目的的未锁定任务换时段，且不改变当天总时长、先修顺序或复测有效时段。跨天、跨科、增减活动或改变目标均预览确认。受影响事件后产生一次重排建议，未采纳时不重复堆积同类卡片。

预览保存 `previewId`、学生／目标／证据／日历版本、规则版本及具体任务；确认应用该版本。依据已变化则返回冲突并重新预览，不能静默重算后套用不同安排。时间不足保留未排任务及取舍，不增加每日预算或自动降低目标。

## 5. 最小真实后端

建议沿用 React 前端和 TypeScript 领域类型，增加单个 API 服务与 SQL 持久化；先用单实例部署方式，避免首期拆多个服务。具体运行库、数据库产品及部署供应商由实现阶段按已确定环境选择，并记录决定；不要求用户逐一选择工具库。

| 数据组 | 持久化及职责 |
|---|---|
| 用户、会话、个人目标／时间 | 邀请制账户、学生／开发者／内容复核角色；每次请求按服务端身份限定访问范围 |
| 内容包、题目、评分与规则版本 | 表格导入先校验和预览；缺条件／先修循环／无答案／来源问题不通过；发布固定版本，测验绑定版本 |
| 测验、作答、提示、批改、附件 | 服务端计时与计分；提交幂等，事务内只生成一份结果和证据；附件保存实际文件及归属 |
| 学习事件、错因、补救周期、掌握证据 | 记录历史及修订；掌握状态从事实和规则计算，可解释重算 |
| 复习、任务、计划预览及采纳 | 防止重复安排、重复完成及旧预览覆盖新任务；锁定／完成项目保留 |
| 模型服务配置及调用状态 | 密钥只在服务端，学生接口不返回；配置角色与学生隔离；连接、模型列表、能力测试分别记录 |

服务端统一验证输入、归属、状态转移和版本，不允许前端直接提交「已经掌握」、分数或计划通过状态。`bootstrap` 可暂作当前学生的前端兼容视图，但不能返回整个服务数据库、其他学生、未发布内容或模型密钥；查询逐步拆开。

现有演示数据保留在 mock 环境。真实学生从干净账户开始；重设演示、固定日期和本机调试开关不操作真实记录。本机草稿若保留，需按用户及测验隔离，登出／换用户时不能恢复上一个学生的草稿。

首期附件支持上传、授权查看及人工复核。OCR 和语音识别后续；模型没有通过图片能力测试时，不声称已分析图片。

## 6. API 契约与现有集成点

以下为拟调整的契约，实施时同步 OpenAPI、客户端及 mock，不表示接口已经存在。

| 范围 | 拟增补行为 |
|---|---|
| 会话／身份 | 登录、退出、当前身份；邀请分配；开发者及内容复核访问控制 |
| 测验创建／读取 | 返回题面投影，不带评分密钥或可提前读取的提示；绑定内容与蓝图版本 |
| 作答／提示／提交 | 保留保存答案和提交入口；增加服务端提示／答案展示事件及幂等键；返回覆盖、批改与证据状态 |
| 错题／复核 | 查询限本人已开放反馈，提交错因确认／更正；复核入口受角色限制 |
| 复习／结果建议 | 返回今日预算内活动、未排项目及原因；完成回顾和新增独立证据分开 |
| 计划 | `preview` 返回 ID 和版本；`apply` 必须引用预览及预期版本；旧预览返回结构化冲突 |
| 附件 | 真实二进制上传及授权读取，不能只存文件名和大小 |
| 开发者模型设置 | 配置、获取模型列表、选择、测试、停用；按实际服务协议适配，无列表时允许手填 model ID |
| 内容审核 | 表格上传／校验预览、导入草稿、逐题复核与发布；保留版本及操作者 |

已阅读代码确认的迁移点：

- `src/types.ts`：`PublicQuestion` 目前只去掉答案／解析而保留提示；`Answer.hinted`、`WrongItem.resolved` 和 `Evidence` 不足以表达新规则。
- `src/api/mock.ts`：提示独立性依浏览器字段；`/wrong/:id` 返回完整题目；`/plans/apply` 重新计算方案；`/attachments` 只登记元数据。这些不能原样复制为正式后端行为。
- `src/api/client.ts`：现有 API 入口可作为迁移接缝；SSE 当前主要处理 delta，需补消息 ID、完成、失败和中断状态。
- `src/pages/Quiz.tsx`：草稿键只含测验 ID，提示本地标记，提交后刷新数据；需对应身份隔离、服务端提示及新结果卡。
- `src/domain.ts`：保留适用的计分和时间约束函数；替换掌握度、目标排序和轮转排程，不为旧示范规则新增永久依赖。
- `scripts/generate-openapi.mjs`、`public/openapi.json`：当前是 mock 契约；随正式接口更新并做一致性检查。

真实服务模式的学生构建产物不能携带审核答案库；演示题库独立构建／按模式隔离并检查产物。已经向本人开放的历史批改答案允许查看，但该题不能再次成为未曝光的独立题。

## 7. 模型的职责与故障体验

模型根据审核材料、当前学习任务和必要的本人证据提供讲解、分层提示及错因候选；引用可追溯内容位置。日历先由规则代码生成方案，模型解释依据或给结构化建议，后端校验后形成待确认预览。

模型不直接写成绩、掌握状态、考试日期、院校公式或已采纳任务。正式测验不向学生聊天接口提前开放参考答案；测验中请求教学帮助须记录辅助使用。AI 自由生成题保留陪练标记。

服务不可用时，已发布材料、客观测验、复习及规则排程继续可用；AI 区域显示具体失败状态，可重试。停止生成、断线和重试有消息 ID，不能重复写用户消息或重复改变证据。真实模型及能力验收待用户在开发者配置中提供服务后进行；本计划没有预设真实 API 地址或虚构成功调用。

## 8. 实施批次与验收

| 批次 | 交付物 | 进入下一批次的依据 |
|---|---|---|
| M1 内容与规则 | 两个内容包、来源／标签映射、评分点、先修和初始规则、审核导入格式 | 蓝图覆盖诊断、补救与隔时复测所需的不同题；正式题有复核记录，缺内容有明确状态 |
| M2 后端与记录 | 账户隔离、内容版本、作答／提示／提交、真实文件存储 | 两账户无法读取或修改彼此数据；重启后恢复；提交重试无重复分数／证据 |
| M3 学习内核 | 诊断、错误候选与更正、补救暂停、掌握及复测 | 同题、提示、答案曝光及待批改情形不会升级正式掌握；跨时段有效证据能按规则升级 |
| M4 目标与日历 | 受限组合比较、预算内任务、结果卡、带版本预览／采纳 | 最低门槛／Best N／未知数据案例正确；预算与锁定保留；旧预览不会覆盖新安排 |
| M5 真实 AI 与界面联调 | 开发者配置、模型列表／手填、测试、学习与日历接入 | 提供真实服务后验证一次完整教学与解释流程；失败／停止／重试可恢复；无密钥进入学生响应 |
| M6 部署与试用 | 有持久化和恢复验证的试用环境，3–5 人两周观察 | 先通过技术及内容验收，再邀请；记录实际可用性、内容问题和前后测证据范围 |

学习规则尽量作为可单测的纯函数；服务端测试聚焦归属、幂等、版本冲突及事实记录；浏览器检查完整用户旅程和手机使用。原有 23 项演示测试不自动等于新流程通过。

最低验收案例（当前均为计划，未执行）：

1. 学生成绩未知时保留未知；目标低于必要门槛时出现冲突，不自动改目标。
2. Best N 中某科单独升一级没有收益、连续提升后才替换入选时，组合比较能发现；不重复累加替换收益。
3. 同权重不同成本区间会改变比较结果；成本缺失或区间重叠时显示不确定性，不保证低等级一定更划算。
4. 初测漏答、答案错误和待人工评分分开；未覆盖技能不计作已失败。
5. 提示后、看过答案后、重做同题及同一家族刷题不会绕过覆盖／独立证据规则。
6. 学生纠正错因后补救使用新判断；原始依据与修订记录仍在。
7. 同周期第二次失败暂停自动追加，换聊天不重置；前置不足时不自动推进依赖它的高级题。
8. 隔时复测在香港跨日期但未满有效间隔时，不提前升级；系统重启后仍可继续复习。
9. 每日复习、诊断及补救全部占预算；零分钟、锁定任务及排不下的复测有可见处理。
10. 测验后仅单元改善时，卡片不宣布整科达标；查看冲高也不改变目标。
11. 预览后修改目标／证据／任务，再应用旧方案得到冲突；双击应用不生成重复任务。
12. 学生 A 切换至 B 后不会恢复 A 草稿或附件；直接请求他人 ID 也不能读写记录。
13. 未提交题面、错题接口、构建产物不泄露未开放答案；已提交反馈可正常复习。
14. 模型列表失败、选中模型不可用、超时、停止和重试均有准确状态；AI 失败不阻断客观测验与规则计划。

试用观察建议：每位学生能独立完成至少一次完整流程及一次隔时复测；记录需要人工帮助的步骤、内容错误／歧义、计划采纳与实际完成情况。数据丢失、跨账户访问和重复正式结果须先修复并复验。两周小样本用于判断流程是否可用，单元前后表现需注明题型与辅助程度。
