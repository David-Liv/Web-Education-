# 下一阶段建议：已有考卷导入与证据驱动诊断

日期：2026-10-28。状态：本轮分析建议，未获实施授权、未修改业务代码。延续用户要求保留后续功能备注；不将讨论中的想法写成已确认决策。

## 1. 推荐方向

把已有考卷作为另一种进入学习系统的入口：上传 → 识别及核对 → 失分／覆盖报告 → 判断哪些初测可省略 → 必要时少量补测 → 补弱及计划预览。

可以让信息充分的学生跳过相应初测。上传数量本身不是掌握依据；只对试卷实际覆盖、识别与评分依据足够的技能作判断。没有考到、缺页或看不清的部分保持未知。后续隔时复测仍可用于检查保留情况，不必重新完成整套入门测试。

## 2. 当前可复用及缺口

本轮读取代码确认：

- `server/app.ts` 已有鉴权上传及本人附件读取，但仅接受指定图片／音频 MIME，尚不接受 PDF。
- `server/models.ts` 的输入是文字消息，尚未发送图片或文件，亦没有实际 OCR／视觉能力测试。
- 已有答案、步骤、人工批改、错因候选及修订、内容版本、证据及日历预览逻辑，可以复用。
- `PilotEvidence` 目前围绕平台测验、平台题号、审核状态及独立性设计。外部考卷不能直接伪装为一次平台测验，或一律填 `reviewed=true`、`independent=true`。
- 初期正式教学只覆盖二次方程、酸碱与滴定；可以扩展全卷分析视图，但必须逐步补充全科知识点与评分映射，才能给出可靠的全科诊断。

## 3. 学生交互

测验入口并列「上传已有考卷」与「做一次摸底」，避免额外增加一层必须经过的入门流程。

1. 上传扫描 PDF 或多张照片；排序、旋转、检查缺页和题目是否跨页。可分别上传原作答、老师批改及答案／评分标准。
2. 填写学科、试卷类型、考试日期／版本、是否限时独立作答、是否已经订正。可不知道，未知不能被默认为独立作答。
3. 后台分阶段处理，显示排队、解析、逐题整理和待确认；支持继续上传缺页、取消、失败重试与按页缓存。
4. 侧栏原图与识别结果对照，优先请学生确认不清晰的数值、正负号、题号及得分，不要求重打一遍整卷。
5. 每题显示原始作答、老师批改、AI 建议及对应技能，四者来源分开；每条判断可回到页码和局部图像。
6. 展示实际得分／待评分／未覆盖范围、失分原因与目标相关性；随后给出「可省略初测」「只补这几项」「先补资料」等行动。
7. 学生确认采用后，形成新的学习证据及待确认日历方案；重用现有预览版本机制。

## 4. 输入质量决定怎样处理

| 材料 | 建议处理 | 初测安排 |
|---|---|---|
| 近期已批改试卷，原作答／题目清楚，得分可核对 | 导入外部表现；重点核对识别及知识点映射，不要求团队给老师重批整份卷 | 可以省略相应已覆盖技能的初测；保留其他技能和后续复测 |
| 未批改，但有适用答案及评分标准 | 先给评分建议；客观项校验，步骤及争议项单列 | 根据可靠部分减少初测；未确认部分作短补测 |
| 只有作答，没有答案或评分标准 | AI 给初步分析和待核对判断，不制造确定分数 | 可以帮助选下一道题，必要部分再验证 |
| 空白试卷、答案抄本、订正后版本 | 可用于资料导读／练习，不证明原来的独立能力 | 不据此直接免除能力验证 |
| 试卷较旧、局部上传、范围偏窄 | 标明日期、缺页及覆盖限制 | 针对不确定、过时或未覆盖能力补测 |

老师批改影像是学生提供的来源资料；没有独立认证教师身份时，不称为已验证教师身份。平台内容复核与外部成绩采用是两个流程：私人考卷分析不应被迫先发布为公共题库。

## 5. 证据与分数规则

- 分开保存原卷分数、老师／学校提供的 DSE 预估、AI 评分草稿、平台已验证的独立证据及个人目标。
- 外部证据可以影响优先级、跳过重复诊断及短测选题；是否参与「初步／较稳定掌握」应另定规则，不能默默绕过 C10–C12。
- 可以区分「已有考卷支持」和「平台新题已验证」两个来源状态。学生确认识别文本不等于确认 AI 评分正确，也不证明独立作答条件。
- 同一题只有一次来源事实；重复上传、重拍或订正不重复增加证据。跨文档去重需结合卷别／版本／题号及内容，不只比较文件哈希。
- 空白可能来自不会、时间不足、没学过或缺页，不能统一认定为知识缺陷。
- 多知识点题按评分点定位，不因最后一个数值错误就把所有关联知识点都判弱；连带错误按适用评分标准处理。
- 旧证据的参考价值随日期、课程适用性及近期表现变化；不宜无限延用，也不因到期瞬间清零。
- 校内测验百分比分数不能直接当 DSE 等级。可先报告本卷表现与能力画像；要展示 DSE 参考范围，需要另有整科覆盖、适用评分与实际校准依据。

## 6. 后续诊断只补最有价值的信息

先问「补测结果会不会改变下一步安排」，再决定出题。候选包括目标关键能力仍未知、同一技能跨卷矛盾、证据太旧、识别／评分争议及某个高收益任务的先修能力。

建议每轮少量新题，例如 3–5 题作为初始交互上限，而非固定测量标准；如果已有足够依据也可零题结束。没有足够题库或时间时，保留未知和可用方案，不强制输出等级。

示例：学生已经正确列出二次方程两根，但把题目要求的较大根填成较小根。可候选归因于条件选择，而非立即安排整套因式分解教学；用一道相近的新题检查判断是否成立。

## 7. 建议的实现顺序

| 优先级 | 工作 | 收益及启动条件 |
|---|---|---|
| P0 | 用选定真实服务验证试卷图片、繁中／英文、手写、公式和版面读取 | 现有文本测试不能代表能读卷；建立少量脱敏、有人核对的题目样本，不自动测试清单内每个模型 |
| P1 | 数学已批改试卷导入、原图对照、逐题外部证据及初测减免 | 尽快降低重复测试负担；先做两个已开放单元的可靠学习联动 |
| P2 | 扩展未批改卷评分草稿与人工例外复核，再扩全数学覆盖 | 先验证与参考评分的差异，不急于推出未经校准的整科等级预测 |
| P3 | 自适应短测、跨次考试趋势及证据更新 | 只有必要时验证，避免反复测已经有依据的部分 |
| P4 | 用实际补弱、有效用时及隔时复测修正个人成本估计 | 接回现有目标组合比较；一次读完或后台停留时间不等于完成学习 |

老师／审核者的工作聚焦争议、未知和关键样本，不把每位学生的所有上传都变成双人重批工作。上传材料保持本人私有；加入共享题库属于另外的内容发布流程。

## 8. 数据与验收建议

建议增加外部评估、原始页、题目切片、识别版本、原始作答、批改来源、得分／评分点、映射依据、核对状态、证据引用和采用记录。文件解析／模型结果使用单独作业状态，不能在一个普通聊天请求中处理完后只留一段不可复核的总结。

首批校验重点：公式与数值读错、老师批注误当学生作答、题号或跨页条件丢失、评分点差异、知识点误标、由不确定材料错误宣布掌握，以及实际省下多少重复诊断。模型自报「95% 把握」不能代替这些验证。

最低验收例：

- 只上传卷二时，不推断卷一能力或整科等级。
- 同卷重传与订正不重复加证据；撤销采用可回退对应派生状态，并标记需重新预览的日历。
- 正负号／指数或老师分数不清时显示局部原图和待确认，不自动补成最可能答案。
- 老师分数与 AI 评分不同，两者均保留；AI 不覆盖老师来源记录。
- 来源充分时确实跳过相应初测；缺口只触发相关补测。
- 所有报告、切片和评分仍按学生身份隔离；解析失败不丢原文件。
