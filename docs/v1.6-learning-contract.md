# v1.6 learning contract

Student-facing names use “knowledge point”; the internal unit is `maths-quadratic`, with six skill IDs in `src/quadratic-skills.ts`.

## Question and attempt identity

Private `StudentState.practice.items` snapshots include original wording, reference, grading rule, content hash and source (chat/message, document/lesson/version, or quiz/ordinal; Tutor binding where applicable). Public `/learning` and bootstrap expose identity and wording only. They omit reference answers, hints, rules and grading criteria. `/learning/chats/:id/questions` can register an older owned chat or saved document without AI. Existing coarse attempts retain their original skill scope.

`POST /chats/:id/messages` accepts `questionId`; explicit Q numbers are resolved against the selected document or unique lesson/version. Ambiguous or unowned identities fail before provider calls. Ordinary questions and acknowledgements do not create attempts. A supported answer is stored before generation, with pending feedback; hidden `teaching.attempt` metadata may supply reference feedback in the same response. Code results override model disagreements. Stop, expiry and provider failure leave a saved, unscored answer. A repeated request retains one attempt.

`teaching.exerciseSkills` is a bounded array of primary skill IDs for exercises in ordinal order. `teaching.attempt` contains questionId, score (0–100 or null), verdict, text and reason; null requires uncertain. Invalid metadata is not adopted. It never changes formal reviewed-bank evidence or whole-subject grades.

Assistance is tied to content hashes. `POST /learning/items/:id/assist` records hint/answer/discussion before returning owned content, including assistance on active practice packs. Repeated content, known assistance, feedback exposure and corrections cannot become a fresh independent attempt by changing Tutor or closing the question chip. Chat references remain AI references unless an actual code rule can verify them.

## Targeted packs and reviews

`POST /studio/quizzes`: existing purpose, source and requestId plus optional `skillId`, `retest`, `reviewId`. `source:auto` prefers verifiable original variants, with bounded novelty search against registered questions. Insufficient coverage falls back to the quiz generation contract. Count is 1–5 (default 3 in UI); retests require a skill and 1–2 questions. Review IDs are owned and match the skill. Request reuse with changed inputs is rejected.

Numbers, fractions, bounded arithmetic and radicals use the existing safe expression parser; unsupported syntax stays uncertain or receives one AI reference grade. Modelling requires a matching equation or reference review. Empty answers do not trigger AI or create review activity. Results and methods remain separate. `GET /studio/quizzes/:id/pdf` renders the saved snapshot, questions first, with the same ordinals and a controlled return link. It never generates new questions or exposes reference answers.

Completed work queues one review per skill and learning date, with source question IDs. The next-day date is an invitation to practise, not evidence of elapsed 24 hours. Stable provisional labels require at least three independent questions, at least two families, a span of 24 hours and the existing score conditions. Early practice is allowed. Review completion requires answers, and normal plan preview/apply protections remain active. Missing capacity remains visible as unscheduled work. No persistent worker is introduced.

## Appeals and billing

`POST /learning/attempts/:id/appeal` requires reason and a stable requestId. The first transaction claims one review, retains previous feedback and excludes the disputed judgement. Code verifies first; otherwise one site-wide reviewer call is funded by the platform, even with zero student allowance. Duplicate claims reuse the record. Corrected/upheld judgements replace the same attempt; unknown or expired work remains excluded. No extra attempt or automatic retry is created, and an obsolete chat response cannot overwrite an appeal.

Ordinary chat and attached feedback share one operation. Quiz generation uses quiz defaults, separate AI pack grading uses evaluation defaults, and internal review/repair does not add student charges. Code grading, registry reads, repeat views and PDF exports use no AI credits. Actual API costs remain platform costs where explicitly stated.

All routes use existing session ownership, same-site mutation checks, revision-locked JSON persistence and private storage. There is no new schema, public data permission or paid infrastructure.
