更新：2026-10-27。本文是产品设计参考，不是当前代理或学生界面必须逐字执行的提示词。

## 1. 采用、调整和保留

| 原 prompt 条款 | 可转成的产品能力 | 调整与边界 | 状态 |
|---|---|---|---|
| §0 鼓励、降低难度 | 先指出合理部分，再解释具体偏差；提供更基础例子或暂停选择 | 不因「??」、短回复等就断言学生的情绪；只视作可能需要帮助的信号 | 建议 |
| §1 TEACH / SOLVE / SELECT | 学习讲解、引导解题、目标选题三种任务状态 | 学生看到自然语言名称，模式与课程、目标和当前知识点一并保存 | 建议；现有聊天已有部分模式入口 |
| §2、§12 思考草稿／自我复盘 | 可核对的判断摘要：依据、引用、选中规则、下一步行动 | 不要求或展示模型内部思考草稿；用简短解释和结构化事实记录支持复核，不要求每次强行找瑕疵 | 调整建议 |
| §3.1 切片、阶段小结 | 一小块教学后给少量练习，再决定下一步；可主动请求更快导读 | 块大小按材料密度和学生表现设置，不机械固定 5–15 页；快读不直接标记掌握 | 建议 |
| §3.2 顺序、来源、课程工具 | 引用材料位置、先修边界、逐步解释、区分原文与补充 | 严格物理顺序只用于资料导读；目标补弱按先修和收益选择内容 | 模式原则已确认 C27；解析和定位后续 |
| §3.3 引导发现 | 分层提示，学生可以选择继续提示或完整讲解 | 先修证据不足时先教基础；不能根据自报已知就强行要求推导 | 建议 |
| §3.4 引导问题上限 | 避免连续盘问，提示有上限并提供直接讲解入口 | 引导教学提问与正式诊断题分开记录 | 建议 |
| §4.1 概念、应用、复合、弱点融合 | 不同题型覆盖不同能力，不只识别熟悉题面 | 正式证据依审核题／模板；复合题必须标注对应技能，不能重复计入升分收益 | 部分规则已确认；扩展题型为后续 |
| §4.2 Find the Bug | 从受控错误解法中定位逻辑断点 | 必须有正确参考解、错误步骤与解析；错误示例单独标记，不进入正常教材知识库 | 后续 R08 |
| §4.4 错误归因、一次重试、刹车 | 从错误依据选择补救动作，避免无限重做 | 不能仅凭一个错误答案归因；第二次失败后检查前置知识，不能总是直接推进下一单元 | 已确认 C24–C26，待实现 |
| §5 六步解题 | 目标、条件、方法、结构、推导、答案等教学模块 | 展示可学习的解法，不强制每题六个冗长标题；学生作答步骤须另行采集 | 建议 |
| §6 选题 | 围绕目标、覆盖和难度选择正式题或陪练题 | 排序由可检查规则决定；AI 只能给建议／解释 | 方向已确认 |
| §7 知识库存 | 可追溯的知识状态、当前证据及自评记录 | 自报已知、看过讲解和粘贴库存只作自评／历史记录，不直接升级正式掌握 | 已确认边界 |
| §8 弱点历史 | 保留错因、关联知识、补救和后续复测 | 一次重答正确不能删除历史或宣布稳定掌握；用不同审核题跨时段确认 | 已确认边界 |

## 2. 错题归因的建议结构

现有页面可以让学生选择一个错因，但还没有系统归因。「观察」「推测」「确认」分开的原则已确认（C24）；下表字段仍是待实现的结构建议。

| 内容 | 需要记录什么 |
|---|---|
| 原始作答 | 题目与版本、最终答案、可用步骤、附件、作答时间、提示／答案是否已展示 |
| 观察依据 | 哪一步或哪句表现与评分标准不符；若只见最终答案则明确缺少过程 |
| 错因候选 | 概念混淆、条件遗漏、方法／工具误用、运算／单位失误、推导跳步、直觉偏差、前置缺口、题意／表达理解、待确认 |
| 来源 | 审核题中的干扰项映射、确定性校验、AI 建议、学生自评或教师复核 |
| 依据是否充分 | 直接证据／有支持但未确认／不足；不靠模型自报百分比包装确定性 |
| 确认与纠正 | 学生接受／改选／不确定，教师修订，保留修改前后及版本 |
| 补救动作 | 短解释、检查条件／单位、补前置知识、逐步示例、同类新题或延后复测 |
| 后续证据 | 换题独立表现及隔时复测；原题改对与稳定掌握分开 |

例如：只看滴定题的最终数值不能确定学生是单位换算错误、摩尔比错误还是输入失误。若步骤明确把 cm³ 原值直接代入要求 dm³ 的公式，可以指出该步骤的单位不一致；仍应避免据此给学生贴上永久标签。

同一题可以有主错因和次错因候选。题目有意植入的错误示例与学生实际犯错必须分开记录。

## 3. 建议的教学与补救流程

1. 读取当前目标、课程边界及相关知识点证据；缺少证据不等同零能力。
2. 识别任务是资料导读、目标补弱、引导解题还是正式测验；学生可明确切换。
3. 前置知识具备时可提供引导发现；不足时先讲基础，不用反复追问代替教学。
4. 陪练可逐层给提示，随时可请求完整解法；提示、解法展示和原始作答分别保存。
5. 答错后先给可支持的具体反馈；证据不足时只保留候选，必要时最多追加一次短追问（C24–C25）。
6. 同一补救周期允许一道同类新题重试；再次失败暂停自动追加，展示完整解法并给补救选择（C26）。学生可主动继续；不据错误次数直接降低整科等级。
7. 暂停后记录未解决弱项，提供基础补救或其他不依赖此弱项的内容；不得把暂停当成已掌握。
8. 在后续独立审核题及隔时复测中检验迁移与保留表现，更新知识点状态。
9. 科目测验结束后综合新证据与目标相关性；只有有价值的调整机会才显示下一步卡片。

## 4. 正式证据与辅助信息

- 正式证据：合适范围内的审核题、独立作答、题型覆盖与时间信息，满足该知识点的规则版本。
- 辅助信息：聊天解释、自述已知、翻卡、提示后作答、陪练题、AI 主观题评论、OCR 未确认结果等。
- 同一原题记住答案不等于迁移；看过答案后的重答保留为学习过程，不能重新包装为首次独立证据。
- 学生记录属于应用数据库；不把大模型聊天历史或模型所谓「全局记忆」当作唯一权威记录。
- 若没有可追溯的基线失分／题型映射，只能解释相关能力的改善，不能输出假的精确加分。

## 5. 待补的数据实体与后端职责（建议）

这是概念清单，不是已定案的数据库或接口设计。

- 审核内容版本：知识点、先修关系、题型、评分步骤、错误映射、目标相关性及成本范围。
- 作答与步骤：原始输入、附件、提示层级、答案展示、题目来源、正式／陪练用途。
- 错因记录：候选、依据、来源、确认状态、学生／教师修订。
- 教学会话：当前块、资料位置、任务模式、提示状态、补救周期与暂停原因。
- 掌握证据及规则版本：不同题目／题型、时间跨度、辅助程度、当前状态与历史。
- 目标与计划建议：使用的课程公式版本、假设条件、成本估计、可行性、学生采纳记录。

后端应负责访问范围、持久化、提交幂等、审核内容与答案的访问控制、学习时间预算和结构化输出校验。模型服务提供讲解或候选判断；经过规则验证的状态转移才可更新正式记录。API 由开发者配置，用户已拒绝固定 HK$100 测试限额，见 [开发者模型设置](developer-model-settings.md)。

## 6. 验收场景草案（未执行）

- 同一最终错误答案但作答过程不同：不能被强制归为同一种原因；无过程时允许未知。
- 学生修正错因后，下一次补救使用新分类，原始作答仍保存。
- 提示后答对显示学习进步，正式独立证据不增加。
- 原题第二次答对可以显示已订正，不直接显示稳定掌握。
- 不同审核题跨时段通过后，才按规则更新较稳定状态。
- 连续失败触发暂停，但不会自动打开依赖同一未掌握前置知识的高级内容。
- 自报已知、粘贴旧库存或翻完卡片，均不能直接改变正式掌握状态。
- 找错题中的故意错误不会被当成正确教材、学生历史错误或正常参考解。
- 同一个评分步骤被多个知识点支持时，得分改善空间不得重复累加。
- 上传资料的页码缺失或 OCR 不确定时不伪造引用位置；目标补弱的跳转有明确模式说明。
